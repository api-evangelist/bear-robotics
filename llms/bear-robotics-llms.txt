# Bear Robotics

> Bear Robotics builds AI-driven autonomous mobile robots for hospitality and service
> environments — the Servi family (Servi, Servi Plus, Servi Q, Servi Clean), the Carti cargo
> line, and Kinisi — managed through the Bear Universe cloud platform. Founded 2017 by former
> Google engineer John Ha, headquartered in Redwood City, California, and now majority-owned by
> LG Electronics. The Bear Cloud API is a gRPC-first third-party interface for controlling
> robots, receiving robot state, and managing fleets.

## API

The Bear Cloud API is gRPC-first. The service is
`bearrobotics.api.v1.services.cloud.APIService` on `api.bearrobotics.ai:443`, with 39 RPCs —
27 unary and 12 server-streaming. A REST projection generated by google.api.http transcoding
covers 23 of the unary RPCs at `https://api.bearrobotics.ai`; the streaming RPCs have no REST
equivalent. Every REST operation is a POST with a JSON body, including reads.

Authentication is an API key exchange, not OAuth. POST a credentials JSON
(`api_key`, `secret`, `scope`) to `https://api-auth.bearrobotics.ai/authorizeApiAccess` to
receive a JWT, then send `Authorization: Bearer <JWT>`. Refresh roughly every 30 minutes. API
keys are issued by a Bear Robotics account manager; there is no self-serve signup.

## Capabilities

- Mission — create, append, batch-create, batch-append, update, workflow, skip goal, clear status, charge
- Locations & Maps — get location info, get map, get current map, switch map
- Localization & Navigation — localize robot, set pose, subscribe pose / localization / e-stop
- Robot Status — get status, subscribe status / battery / navigation / error codes
- Robot System — get system info, run system command, subscribe network / online status
- Fleet Management — list robot IDs, get available locations
- Servi — calibrate trays, subscribe tray statuses, delivery and bussing missions
- Carti — control conveyor, get conveyor index, subscribe conveyor status, traverse missions
- Webhooks — create, list, delete subscriptions for `mission` and `battery` events

## Things an agent should know before calling this API

- **It moves physical machines through occupied space.** Mission creation, `SwitchMap`,
  `SetPose`, `LocalizeRobot`, `ControlConveyor`, `CalibrateTrays` and `RunSystemCommand` all
  have physical consequence. There is no sandbox and no dry-run.
- **There is no idempotency key.** A command RPC that times out returns `DEADLINE_EXCEEDED`
  (HTTP 504) after 10 seconds, and the timeout fires at the cloud service rather than at the
  robot — so the command may already have executed. A blind retry can double-enqueue a mission.
- **Streaming is best-effort**, not at-least-once, and streams close after 60 minutes.
- **The webhook body is snake_case** while the management API is camelCase. Deliveries are not
  signed; authenticate them with a custom shared-secret header.
- **`Mission` is a three-level discriminated union** (family → kind → params). Most integration
  errors live here.
- **The webhook operations are missing from the OpenAPI document** — they exist only in the
  proto and in docs prose.
- Errors are gRPC canonical status codes with `google.rpc.Status` details, not RFC 9457.
- No pagination, no rate limits published, no status page, no SLA.
